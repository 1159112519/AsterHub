# AsterHub 功能接入与维护标准

状态：从本轮基础框架重构开始执行。文档是项目内部规范，不显示给使用者。

## 接入前

填写功能目的、所属设备、入口位置、用户完整路径、数据/任务生命周期及支持平台。查询公共组件目录；已有能力必须复用，特殊需求先完善公共约定。监控信息优先，工具入口位于监控之后。用户已撤销的设计不复活；不得顺手删掉原有更新、反馈、托盘、终端或文件功能。

## 实现顺序

1. 明确数据/状态/权限与安全边界；只读操作、后台任务、可恢复文件操作分别处理。
2. 使用 MonitoringLayout/ToolLauncher/ToolScene 放入口与独立工作区；使用 Button/Toolbar/ThemedSelect/FormDialog/公共浮层。先复用，再增加业务专属内容。
3. 将交互绑定到语义动效，不在业务页写另一套时长和缓动。默认非线性，hover/focus/pressed 与 enter/back 都纳入验收。关闭、快速往返、偏好改变时释放资源并落到正确终态。
4. 异步请求使用 request scope / AbortSignal；共享轮询使用 polling resource；缓存说明容量和失效条件。取消本地等待不等于终止宿主任务。
5. 功能单元必须完成“打开—操作—离开—回来—完成/失败—退出”的闭环。页面跳转不销毁应继续运行的后台任务，也不留无用请求与动画引用。

## 合入前清单

- [ ] 主次正确：监控在前、工具在后；没有重复路径、重复按钮或开发用宣传文案。
- [ ] 排版正确：内容和按钮有统一边距；字号与控件协调，数字不挤动图形；没有遮挡/重叠/横向溢出。
- [ ] 动效完整：入口悬停、点击进入、返回、对话框和进行中状态；减少动态效果仍能操作。
- [ ] 状态完整：首次无数据、部分能力不支持、断线、失败、取消、完成；硬件清单不因断线清零。
- [ ] 设备隔离：切设备后会话/任务归属正确，旧请求不能覆盖新页面。
- [ ] 视觉兼容：五种皮肤、窗口收窄、125%/150%缩放；字体回退与原生窗口另验，不以浏览器截图冒充。
- [ ] 生命周期：反复进出后监听器/任务/克隆节点/缓存有明确上限。先找泄漏，再考虑可选缓存优化；不得牺牲外观和功能。
- [ ] 功能保留：更新、反馈、托盘、终端、文件等既有入口与行为没有丢失。
- [ ] 证据完整：行为测试、构建、浏览器动作和原生验证分别记录。测试范围之外明确写未验证。

## 可执行检查

在 desktop-preview/web 下运行 npm run test:foundation、npm run check:foundation、npm run build。

本地 Vite 的 /foundation.html 是实际控件组合场景；它不加入正式用户导航或安装包构建。新增公共控件须在该页或对应页面有可复现的状态场景。

检查脚本先约束已经迁移的范围，逐步扩大；不为了通过检查粗暴删除旧兼容样式，不增加只检验实现细节的无意义测试。

## 发布与维护

应用变化使用版本工具并更新用户能理解的 CHANGELOG；私钥和凭据不得进入源码或报告。构建和隔离安装/卸载/数据保留验证通过后，按既有签名、官网和下载验证流程交付。更新发生失败必须记录实际阶段，禁止将浏览器测试当成原生验收或将临时预览当作固定更新服务。

缺陷修复顺序：复现 → 明确公共层还是业务层 → 先覆盖错误行为 → 修公共原因 → 复查其他消费者 → 更新证据。不得每个页面再追加一段互相覆盖的修复。

近期更新由构建前从 CHANGELOG 自动生成，禁止再手工维护另一份版本列表；当前版本缺少日志时构建必须失败。
