# AsterHub 产品基础框架设计与实施计划

日期：2026-11-03。状态：已获实施授权，分阶段接入和验证。

## 目标与优先级

让新增功能主要定义业务内容；视觉、交互、动画、图表、连接、任务和桌面行为通过公共能力复用。优先级：功能与数据安全、外观与交互体验、响应性能、内存节约。优化内存必须有基线和验证，不能取消动画、清空有效数据或强制牺牲常用缓存。文件名、目录层级和组件参数应明确职责，不建设脱离当前业务的通用引擎。

## 依赖方向

业务页面 → 公共 UI、动效、图表、设备和任务接口 → 设计令牌与生命周期工具。桌面宿主只通过现有桥接交互。页面可以使用特有几何算法；不得在业务页重复实现公共按钮、动效偏好监听或请求清理。不为网站强套桌面窗口布局，网站可共享品牌规则。

## 核心约定

1. 字号按用途分层，数字等宽；文件矩形按面积调整，在可读下限外隐藏标签并通过悬停呈现。DPI/字体回退也纳入清晰度验收。
2. 皮肤颜色、状态颜色、装饰色分离，保留已认可经典黑和存储柔和彩色块。
3. 按钮的图标用专用参数传入，统一间距、忙碌/禁用及可访问名称；不增加与场景无关的确认。
4. 浮层靠近来源、优先右侧、避开导航，支持点击外部/Esc，嵌套只关闭最上层；模态对话框另管焦点。
5. 动画是状态变化的连续表现。默认非线性；共享偏好与取消机制；禁止连续点击叠加已无用的时间线。真正时间数据不因动画改变。
6. 图表按时间推进，缺样保留断点；范围查询和悬停分离，不在悬停时重算档案。缓存按容量和设备归属淘汰。
7. 连接中断保留已确认硬件和最后读数，标记过期。恢复成功后更新。设备删除与暂时没有快照不同。
8. 异步请求明确成功/失败/超时/本地取消/销毁；本地取消只停止等待，后台扫描取消仍调用宿主 storage.control。
9. 任务离开页面后可继续，统一共享任务快照避免重复轮询；订阅归零时清理轮询和监听器。只在明确支持时提供暂停或恢复。
10. 更新、反馈、托盘、终端、文件保留，不将远端真实业务用作破坏性测试。

## 内存优化策略

首先测量初始、反复打开/关闭浮层、反复切换历史、离开任务页后的对象/监听器/缓存数量与浏览器堆趋势。有价值的动作：共享偏好监听、移除结束动画引用、界定 LRU、取消过期等待、清理已关闭终端索引、共享任务轮询。不追求单个最低数字；完整桌面包含宿主和 WebView2 子进程，浏览器堆不能冒充整机私有内存。开发环境和安装包分别说明验证边界。

## 页面与流程标准（2026-11-03 补充）

监控页面的固定优先级：页面身份 → 监控筛选/指标/趋势/设备状态 → 按需任务状态 → 工具入口。工具不是监控的首屏广告。入口使用 ToolLauncher；以 ToolScene 衔接进入和返回，优先保留来源关系和返回滚动位置。工具进入独立工作区，不能把复杂操作塞在监控页卡里。

表单使用 FormDialog：头部、统一 24px 内容边距、16px 字段间距、独立操作区、12px 按钮间距。窄窗口内容边距 20px。已有复杂偏好设置布局显式保持 custom，不套表单结构。业务页面不得靠手工加一段 padding 修复本可共用的弹窗。

交互流程：入口 hover/focus → 进入工具 → 选路径 → 启动 → 后台进度 → 离开页面 → 返回任务/结果 → 取消/恢复。每一步必须有出口和明确状态；只有业务要求的危险操作需要确认。减少动态效果仍需完整表达状态。

维护流程和可执行验收见 FEATURE-WORKFLOW.md。新增功能完成的标准包括布局优先级、入口反馈、进入/返回、弹窗内容区、空数据、异常、窄窗口、皮肤和资源释放；不是“按钮能点”即完成。
