# AsterHub 界面与动效一致性要求

## 字体与信息

- 正常桌面缩放下，正文与辅助文字至少 14px；设备名约 15px，主要读数依层级放大。字体、字重、单位、行高、留白作为整体调整，不能只放大按钮。
- 不以截图缩小后仍有字就认定清楚；检查实际 WebView2、窄窗口和高 DPI。静止文字保持清晰，避免持久缩放文字层。
- 同类标题、读数、单位和操作大小统一。标签与所属数字接近，与其他组有清楚间距；整块对齐。
- 删除冗余说明和反复强调的 GPU 数量。用户文案描述结果，不放内部测试安排、开发任务或未验证的原始字段说明。

## 布局与交互

- 设备列表紧凑且可读，不误选中文字，可拖拽排序并记住顺序，支持键盘替代操作。
- 表格列宽可调并分别保存。窗口变窄时保留可访问性，不能叠字或用极小字体硬塞。
- 数字位数/单位变化不能挤动邻近图形。百分比、容量与速率区域预留稳定宽度；窄窗口采用明确的另一种排布。
- 弹窗按钮统一右对齐，普通确认操作之间保持约 12px，说明与操作区明确分开。危险操作需要确认与真实目标身份。
- 单 GPU 与多 GPU 都要有合理比例，完整硬件指标在足够宽时同排，窄窗口有序换行。
- 浮层优先展开在内容区右侧，避开导航；自适应位置、圆角、轻微阴影和分层，不使用重阴影争夺注意力。
- 滚动条、选择框、原生窗口及空态跟随主题。启动时组件结构立刻可见，暂缺读数显示“—”；断线保留设备清单和上次读数，注明暂停更新。

## 动效

- 动效必须有来源与用途。卡片到详情、滑块选中、展开收起采用克制的非线性变化；避免突然闪现、整页抽动或无缘由漂移。
- 实时曲线右侧追加数据，整体向左推进；左缘不能临时缺失。真缺失保留断口，不伪造平滑数据。
- 频率、占用与进度条随实际数据平滑更新，避免突跳；CPU 核心采用柔和变化，不做机械闪烁。
- 遵守减少动态效果偏好，不循环播放与数据无关的装饰动画。

## 功能保留与验收

改版保留更新、反馈、托盘、终端与文件等已有能力。对不同设备、1/8 GPU、密集 CPU、900/1100/1600 窗口与不同主题做实际交互检查。Windows 与 Ubuntu 验收分开，公开发布前构建、隔离升级/重启/卸载、数据保留、签名和完整下载散列验证。
